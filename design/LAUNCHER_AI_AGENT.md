# ИИ-агент SIPTrace

Откройте «ИИ-агент» в левой панели лаунчера, укажите ключ AITUNNEL и задачу. По умолчанию используется модель `deepseek-v4.1-flash-1017`. Другая модель должна поддерживать вызовы функций и изображения. Поддерживается браузерная и настольная версия с доступом к [AITUNNEL Chat Completions](https://aitunnel.ru/docs).

Для продолжения работы используйте текущий черновик. Чтобы начать от существующего проекта, выделите его на вкладке «Проекты» и выберите «Копировать выбранный проект» у агента. Черновик и последний план сохраняются локально. Ключ хранится в памяти лаунчера. Снимки текущего запуска доступны в панели. Их содержимое, задание и возвращённые данные инструментов отправляются провайдеру. Кнопка «Сохранить копию в проектах» создаёт редактируемую копию схемы и платы в списке лаунчера.

## Команды

| Команды | Назначение |
|---|---|
| `remember`, `inspect`, `set_targets`, `restore_verified` | Сохранить план и проверяемый состав результата. Запросить объекты и абсолютные координаты площадок. Восстановить последнюю проверенную версию в текущем запуске. |
| `search_library`, `read_library` | Найти и прочитать компоненты и посадочные места из встроенной, импортированной, пользовательской библиотек и проекта. |
| `define_pattern`, `define_component` | Добавить к схеме проектное посадочное место по координатам площадок и прямоугольное УГО по списку выводов. |
| `create_schematic`, `add_sheet`, `set_frame` | Создать схему и листы, настроить формат, рамку, форму и реквизиты основной надписи. |
| `place_component`, `set_component_labels`, `move_schematic`, `delete_schematic` | Разместить УГО с разнесёнными подписями, перенести обозначение и номинал относительно центра без изменения проводников, сдвинуть или удалить объекты листа. |
| `wire`, `mark_no_connect`, `add_sheet_text` | Соединить выводы проводом, поставить именованный порт или пометку NC, добавить текст. |
| `create_board`, `board_outline`, `board_rules` | Создать отдельную плату или синхронизировать её со схемой, задать контур и основные ограничения. |
| `place_footprint`, `move_footprint`, `auto_place` | Разместить корпуса на плате, задать положение, сторону и фиксацию. |
| `route_trace`, `add_via`, `auto_route` | Проложить дорожки и переходные отверстия вручную или вызвать штатный автотрассировщик. |
| `add_keepout`, `add_cutout`, `add_copper_pour`, `refill_copper`, `delete_board` | Добавить запретные зоны, вырезы и полигоны меди, пересчитать заливку и удалить объекты платы. |
| `bom`, `simulate` | Получить перечень элементов и запустить встроенное моделирование поддерживаемых цепей. |
| `check`, `screenshot`, `finish` | Выполнить ERC, DRC, сверку контактов, платы и схемы, проверить выход за рамку, получить PNG и сформировать отчёт. |

Параметры команд объявлены в [commands.ts](../src/ui/modules/launcher/agent/commands.ts). Все изменения черновика сбрасывают результаты проверки и снимки. Чтобы завершить задачу с документами, модель должна выполнить проверку, снять каждый лист и плату и отдельным ответом сформировать отчёт. Для сценария с изменениями после просмотра проверка повторяется. `finish` с `status:complete` требует выполнение `set_targets` и отсутствие блокирующих ошибок. Частичный результат сохраняется с `status:draft` и перечислением оставшихся проблем.

## Проектные правила

Системные [инструкции агента](../src/ui/modules/launcher/agent/instructions.ts) требуют сверять распиновку и размеры корпуса с документацией конкретного исполнения, проверять питание и обвязку, сравнивать ожидаемые связи с извлечённым списком цепей и учитывать технологию платы. Для каждого пользовательского УГО и посадочного места команда принимает указание источника. Для проектных решений, которых нет в данных задачи, агент запрашивает недостающие параметры и отражает ограничения в отчёте.

Для оформления схем применяются тип и правила выполнения документа, формат листа и требования к основной надписи из редакции ЕСКД, заданной для проекта. [ГОСТ 2.701-2008](https://protect.gost.ru/gost/details/87f1f382-a055-48b7-ae80-f359ff5e1f4e), [ГОСТ 2.702-2011](https://protect.gost.ru/gost/details/d9c1c334-2a90-45cb-ac00-c31da92d706b), [ГОСТ Р 2.104-2023](https://protect.gost.ru/gost/details/69d422a2-3c0e-4561-a521-0c99f9cf4417).

Инженерный отчёт отражает покрытие встроенных проверок. Итоговое решение о выпуске требует сверки с документацией производителя, требований производства и проверки прототипа. Команды агента описывают доступные операции над документами. Остальные операции доступны в штатных редакторах.

## Контролёр Decisions

В агентный цикл подключена модель `d1.2-ultra` AITUNNEL. Она вызывается перед finish, delete_schematic, delete_board, restore_verified, set_targets и при двух последовательных ошибках инструментов. Контекст содержит исходное задание, план, заявленные цели, фактическое состояние, последнюю проверку и восемь последних команд.

Ответ выбирает continue, revise или restore. Применение revise/restore требует одновременно confidence и вероятности выбранного класса не ниже 0,8. Порог предварительный и нуждается в калибровке на инженерном аудите. Два подряд пересмотра ограничивают повторное вмешательство до прохождения пакета через штатные инструменты, чтобы модель решений не создавала бесконечный цикл отказов. restore выполняется только при наличии проверенной версии. Каждое вмешательство записывается в журнал. При недоступности контролёра остаются проверки инструментов SIPTrace.

При вызове runAgent можно передать onEvent для получения структурированных записей chat, tool, decision, decision_error и checkpoint. Decision содержит стоимость cost_rub, ID ответа, оценённое состояние и вероятности. Через тот же API-ключ оплачиваются запросы основной модели и контролёра. Отчёт нового прогона хранится в audit/agent-decisions-benchmark.
